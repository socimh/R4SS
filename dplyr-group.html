19  Group and reshape

How far is a respondent’s schooling above or below the sample average for their region? How can we compare several questionnaire items when each occupies a separate column? These questions require two different changes to a table. Grouping changes which observations enter a calculation. Reshaping changes what a row represents.

By the end of this chapter, you will be able to:

  • Add regional comparisons while controlling whether grouping persists.
  • Compare overall and regional age positions without changing respondents.
  • Reshape questionnaire items and verify a complete roundtrip.
  • Prepare ordered school-to-work histories and distinguish duration from transitions.

We use the column operations from Chapter 12 and factors from Chapter 15. The earlier custom summary example is optional; the grouping lesson below explains the summary syntax it needs.

The main examples use the prepared GSS extract. Prepare it following Appendix A, then put gss24.rds in your project folder. A final application uses school-to-work histories because the GSS extract has no repeated monthly observations:

library(tidyverse)
library(tidystata)
gss24 <- readRDS("gss24.rds")

19.2.1 Reduce observations to summaries

summarise() returns calculated summaries rather than retaining respondent rows. The earlier custom-summary example was optional, so we introduce the operation here. Start from the ungrouped table. In mean_educ = mean(educ, na.rm = TRUE), the left side names the result and the right side computes it:

respondent_ungrouped |>
  summarise(mean_educ = mean(educ, na.rm = TRUE))
# A tibble: 1 × 1
  mean_educ
      <dbl>
1      14.2

This result has one row: the mean completed years of schooling across all respondents with recorded schooling. It gives each such respondent equal weight. It does not replace respondent_ungrouped.

To request one summary per region for this operation alone, add .by = region:

respondent_ungrouped |>
  summarise(mean_educ = mean(educ, na.rm = TRUE), .by = region)
# A tibble: 4 × 2
  region    mean_educ
  <fct>         <dbl>
1 northeast      14.4
2 west           14.5
3 midwest        14.0
4 south          14.2

The result has one row for each observed region. .by is an instruction inside this call, not a new column or a persistent group. Missing region values would form a separate unknown-region group if present.

Stored groups give the same regional scope without writing .by again:

respondent_grouped |>
  summarise(mean_educ = mean(educ, na.rm = TRUE))
# A tibble: 4 × 2
  region    mean_educ
  <fct>         <dbl>
1 northeast      14.4
2 midwest        14.0
3 south          14.2
4 west           14.5

This result still has 4 rows. A researcher expecting one overall mean would therefore need to remove the groups first. Neither grouping route changes anyone’s schooling. The overall respondent mean differs from an equal-weight mean of regional means: regions with more recorded respondents contribute more observations to the respondent mean.

For a single grouped operation, prefer .by because its scope is visible in that call. Use group_by() when you intend subsequent operations to share the groups, and use ungroup() when that intention ends. Do not add .by to an already grouped table.

19.3 Compare positions within groups

sum() adds numbers, as in the word-count check in Section 17.3. It can also count true conditions: in a logical input, TRUE contributes 1 and FALSE contributes 0. This small calculation has two true values:

sum(c(TRUE, FALSE, TRUE))
[1] 2

The result is 2. For a column, !is.na(age) returns TRUE for a recorded age and FALSE for a missing one. These tests are themselves known for every row, so their sum counts recorded ages without dropping respondents or treating missing ages as age zero.

The age groups in Section 14.5 distinguish fixed intervals from sample quantiles. Grouping introduces another choice: a position in the whole sample or a position within a region. Before using regional quantiles, count recorded ages in each region:

gss24 |>
  summarise(recorded_age = sum(!is.na(age)), .by = region)
# A tibble: 4 × 2
  region    recorded_age
  <fct>            <int>
1 northeast          598
2 west               850
3 midwest            898
4 south             1513

Every region has recorded ages here. An entirely missing or empty group would have no age distribution from which to calculate quartiles; decide how to report that group before applying the calculation. In this extract all respondents also have a recorded region.

First request four overall groups with n = 4. At this step, retain the interval labels so we can see the age ranges:

overall_age_groups <- gss24 |>
  select(id, region, age) |>
  mutate(overall_quartile = cut_quantile(age, n = 4))
overall_age_groups
# A tibble: 3,986 × 4

Comparing two unknown quartile codes gives NA, so adding those comparisons without a missingness rule would return an unknown sum. In sum(..., na.rm = TRUE), the option excludes unknown contributions from this calculation. It does not remove the corresponding respondents from age_positions or assign them a quartile:

age_positions |>
  summarise(
    recorded_age = sum(!is.na(age)),

The table retains all 3986 respondents and their original ages. Unknown ages receive unknown quartile codes. In total, 271 respondents change groups. The code 1 means the youngest quarter of the distribution used by that call, so its age limits can differ between regions. 19.5 Return to one row per respondent

To reverse the reshape, we need to know which values belong in each cell. A key is a column, or combination of columns, that identifies a row uniquely. In the wide table, id should identify one respondent row. In the long table, the combination of id and item should identify one response row.

count() returns one row per observed key and names its row count n. Use filter() to look for invalid keys. In the first check, is.na(id) detects missing identifiers and n != 1 detects identifiers occurring more than once. The | operator means either condition is sufficient. The second check counts combinations of the two columns.

confidence_wide |>
  count(id) |>
  filter(is.na(id) | n != 1)
# A tibble: 0 × 2
# ℹ 2 variables: id <int>, n <int>

confidence_long |>
  count(id, item) |>
  filter(n != 1)
# A tibble: 0 × 3
# ℹ 3 variables: id <int>, item <chr>, n <int>

Both results have zero rows: no respondent identifier is missing or repeated, and no respondent-item pair is repeated. The item names came directly from the three selected column names, so none is missing. Together with the row count, these checks confirm that there is exactly one response position for every respondent and item.

pivot_wider() reverses the direction: it places response positions into columns. The default-name table confidence_positions has the expected name and value columns, so we can start with a call that uses those defaults:

confidence_positions |>
  pivot_wider()
# A tibble: 3,986 × 4
      id conbus       coneduc      conmedic

19.7 Review

  • mutate() can add group means and deviations while retaining the original observations.
  • group_by() stores groups for subsequent operations; ungroup() removes that instruction.
  • summarise() reduces observations to summaries, and stored grouping determines their scope.
  • Within-group quartiles describe relative positions; inspect their boundaries before comparing regions.
  • pivot_longer() changes separate item columns into respondent-item rows; retain missing answers when they mark response positions.
  • count() checks identifying keys; pivot_wider() restores item columns when each key identifies one cell. A list-column warning calls for key investigation.
  • parse_date() interprets month labels; ordered lag() comparisons within each person identify adjacent-month transitions.

Reshaping changes the layout of one table. Chapter 20 next considers how rows and columns from separate tables belong together.

Start from the CSV, reshape it, and parse and sort the months before comparing states. lag(id) lets us identify comparisons that cross a person’s boundary even if the two recorded states happen to be identical:

The ungrouped calculation crosses 711 boundaries: the first month of every person after the first is paired with the preceding person’s final month. Grouping by ID restarts lag() for each history, producing 712 first-month NA values and 50,552 valid adjacent-month comparisons. These first-month values mean there is no earlier observation within this window. They are not missing answers in the recorded state column. Sorting establishes chronology; grouping establishes whose chronology we are following.
