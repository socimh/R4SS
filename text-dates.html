16  Dates and times

A recorded year and a full date have different precision. We should preserve that distinction when converting date text, selecting a time window, or interpreting a measurement. This chapter uses the real monthly economics series supplied with ggplot2; it needs no external data file.

By the end of this chapter, you will be able to:

  • Extract a year from date text and parse a complete date with an explicit format.
  • Diagnose failed conversions and compare results with a known date column.
  • Parse documented month-name text with an explicit language and century check.
  • Select a time window without changing the observation’s recorded precision.

We use column creation and conversion from Chapter 12, text matching from Chapter 15, and row selection from Chapter 6. Load tidyverse and lubridate explicitly; the latter supplies year():

16.1 Read date text

Annual life expectancy does not need an invented month or day. Keep the Year in the earlier Our World in Data (OWID) file as a year. To learn about full date strings, we turn to a real monthly series already supplied with ggplot2. economics contains US economic indicators, including unemploy, the number of unemployed people in thousands. Its date column is already a Date. The dataset documentation describes monthly observations; the first day shown is a representation of the month, not evidence that the entire measurement occurred on that day.

A calendar date identifies a day without a clock time. A timestamp also records a time of day, whose interpretation can depend on its time zone. This chapter works with monthly observations represented by Date values. Its parsing and comparison examples preserve that monthly precision; they do not teach timestamp conversion or time-zone handling.

We will convert those existing dates to character values and back. as.character() returns the printed text representation. Adding date_text gives us an inspectable source for parsing while keeping the original date and economic measurement.

monthly_text <- economics |>
  select(date, unemploy) |>
  mutate(date_text = as.character(date))

For the first extraction examples, retain two existing source months so both centuries fit in a short preview. The familiar membership condition selects their exact text; it does not change the complete monthly_text table:

date_preview <- monthly_text |>
  filter(date_text %in% c("1967-07-01", "2000-07-01"))

Sometimes we want only a component of the text. str_extract() takes character values and a matching pattern. It returns the first matching part of each string, or NA when no part matches. The call returns extracted text without changing the date strings. In a pattern, ^ means the start of a string. Start by extracting the leading 2 where it occurs:

str_extract(date_preview$date_text, "^2")
[1] NA  "2"

The July 2000 string returns "2"; the July 1967 string returns NA. A missing match here does not mean the source date is missing. Our pattern simply did not ask for its first digit.

The character class [0-9] matches any one digit. Keeping ^ restricts it to the first position:

str_extract(date_preview$date_text, "^[0-9]")
[1] "1" "2"

Each ISO date now yields its first year digit. Add {4} to require four consecutive digits. The result is still character text, even though it consists of digits:

monthly_text <- monthly_text |>
  mutate(year_text = str_extract(date_text, "^[0-9]{4}"))

16.2 Parse and check dates

as.Date() converts character values into Date values. With our familiar ISO text, the default conversion recognizes the year-month-day arrangement:

as.Date(date_preview$date_text)
[1] "1967-07-01" "2000-07-01"

The result is a vector of dates. It has not replaced either column in monthly_text. Make the rule explicit before storing the result. The format argument tells R how the source string is arranged: %Y is a four-digit year, %m a numeric month, and %d a day. The hyphens in "%Y-%m-%d" match the literal separators.

monthly_dates <- monthly_text |>
  mutate(parsed_date = as.Date(date_text, format = "%Y-%m-%d"))
monthly_dates

The new column has date type, while date_text remains character. We have retained the original date as a reference. Use the familiar identical() check to compare the complete columns:

identical(monthly_dates$date, monthly_dates$parsed_date)
[1] TRUE

identical() compares the complete objects, including their class and missing values, and returns one logical value. Here TRUE confirms a reversible conversion for the entire column, not just the printed rows. It verifies our representation; it does not independently validate the economic source or make its monthly measurements daily observations.

The last output isolates non-missing source strings whose conversions failed. All 574 monthly records fail this deliberately mismatched format. Read a source value beside the supplied format, correct the format, and repeat the check. Do not fill failed parses with a convenient date: that would turn a conversion problem into invented information.

Some wrong formats can also return plausible but incorrect dates, particularly when the order of month and day is ambiguous. Therefore, absence of NA is only one check. Retain the source strings, inspect the known date convention, and compare complete values when a reference date column is available, as it is here.

16.3 Read month names

A source may write a month name instead of a month number. We need a parser that knows both the arrangement of the text and the language of its names. Readr’s parse_date() returns Date values from character input. Unlike as.Date(), it reports parsing problems in a warning when a non-missing input fails. We first use it on text whose interpretation we have already checked:

parse_date(date_preview$date_text)
[1] "1967-07-01" "2000-07-01"

Its default format is ISO year-month-day. The printed dates should agree with the earlier result. As with as.Date(), the returned vector does not alter the input. The format option makes the expected arrangement explicit:

readr_dates <- parse_date(monthly_text$date_text, format = "%Y-%m-%d")
identical(monthly_dates$date, readr_dates)
[1] TRUE

The comparison checks the complete column again. We have not gained a different time series by using a second parser.

For month names, locale() constructs a set of reading conventions. It does not read data by itself. Inspect its default specification first:

The printed specification includes English month names and abbreviations. It also lists other reading conventions that we do not change here. A locale determines how existing text is interpreted; it does not translate or modify the source text.

Use two real observations from economics to check an alternative representation: July 1993 and June 1999. The strings below transcribe their months using English abbreviations and two-digit years. The original date and unemploy remain alongside them. The condition in if_else() chooses the July spelling for the first date and the June spelling for the other selected date:

month_name_text <- economics |>
  select(date, unemploy) |>
  filter(date == as.Date("1993-07-01") | date == as.Date("1999-06-01")) |>
  mutate(month_text = if_else(date == as.Date("1993-07-01"),
                              "01 Jul.93", "01 Jun.99"))
month_name_text
# A tibble: 2 × 3
  date       unemploy month_text
  <date>        <dbl> <chr>     
1 1993-07-01     8930 01 Jul.93 
2 1999-06-01     5951 01 Jun.99

The table has 2 source months. We have changed their text representation, not their unemployment measurements. The source dates establish the intended years as 1993 and 1999; two digits alone would not document the century.

Pass the stored locale through parse_date()’s locale option. The pattern %d %b.%y expects a day, a space, an abbreviated month, a literal period, and a two-digit year. Punctuation is part of the format, just as the hyphens were in the ISO lesson:

month_name_dates <- month_name_text |>
  mutate(parsed_month = parse_date(month_text,
                                   format = "%d %b.%y",
                                   locale = english_dates))
month_name_dates
# A tibble: 2 × 4
  date       unemploy month_text parsed_month
  <date>        <dbl> <chr>      <date>      
1 1993-07-01     8930 01 Jul.93  1993-07-01  
2 1999-06-01     5951 01 Jun.99  1999-06-01  

identical(month_name_dates$date, month_name_dates$parsed_month)
[1] TRUE

TRUE checks both transcribed strings against the real reference dates, including the century. If a documented month name does not parse, inspect both its spelling and language and the supplied pattern. An English locale cannot identify arbitrary names from another language. Do not treat an absence of missing results as proof that the year or month is right: compare against the source convention too. The day 01 continues to represent a monthly observation, not an event known to have occurred on that day.

16.4 Select a time window

Once parsing is checked, year() from lubridate returns the numeric calendar year of each date. Use a new calendar_year column to make the filtering rule readable. We want the monthly observations from 2000 through 2014, including both endpoint years. The comma inside filter() requires both conditions to hold.

monthly_window <- monthly_dates |>
  mutate(calendar_year = year(parsed_date)) |>
  filter(calendar_year >= 2000, calendar_year <= 2014)

The result retains 180 monthly observations. calendar_year repeats within each year because extraction does not aggregate observations. The unemployment measure still refers to a month and is still recorded in thousands of people. Computing one annual statistic would require a separate, explicitly chosen summary.

This distinction also protects the annual OWID data. A year can locate an annual observation on a graph without conversion into an exact date. Do not append a midyear month or day merely to satisfy a preferred storage class. Preserve what the source records and choose a representation appropriate to the comparison.

16.5 Review

  • str_extract() returns a matching substring; extracting a year does not validate the complete date text.
  • as.character() and as.Date() change representation; an explicit format and a complete comparison help check conversion.
  • parse_date() reads dates with an explicit format; locale() specifies the language of recorded month names. Check the century against the source.
  • year() extracts a calendar component without changing the observation’s recorded time precision.
  • Retain source strings, diagnose failed conversions, and avoid inventing days for annual or monthly measurements.
