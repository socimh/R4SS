12  Create variables

A survey’s recorded answers are often the starting point for an analysis. Before calculating a new measure, we need to know how to name a column, add one, and retain the returned table. These operations should preserve the connection between a respondent and their answers.

By the end of this chapter, you will be able to:

  • Rename a variable and distinguish creating a column from replacing one.
  • Create a column from an existing column while preserving row alignment.
  • Save a returned table and distinguish it from the unchanged input.
  • Convert numbers and text explicitly and diagnose information lost in conversion.
  • Create descriptive text while preserving source answers and identifiers.

We build on selecting columns and observations, sorting, and the pipe. Our data are the prepared 2024 GSS respondents. This chapter establishes the mechanics of changing columns and text. Chapter 13 next applies an operation to several columns, before Chapter 14 develops calculations and conditions. The optional programming chapters are not prerequisites.

Prepare the extract following Appendix A, then restore the saved file in your project folder:

library(tidyverse)
library(tidystata)
gss24 <- readRDS("gss24.rds")

Keep the ID, hours worked last week, and years of schooling. These are observed answers, including their original missing values:

work <- gss24 |>
  select(id, hrs1, educ)
head(work)

1     1    43    16
2     2    NA    16
3     3    NA    14

There are 3986 respondents in work; only six are displayed. hrs1 refers to the previous week, not a respondent’s usual schedule or commuting time. Its missing values do not imply zero working hours. The examples below change table structure without changing the recorded answers.

12.1 Renaming variables

The abbreviation hrs1 is concise but gives little information outside the codebook. rename() returns a table with changed column names. Write the new name on the left of = and the existing name on the right:

work |>
  rename(hours_last_week = hrs1)
# A tibble: 3,986 × 3
      id hours_last_week  educ
   <int>           <dbl> <dbl>
 1     1              43    16
 2     2              NA    16
 3     3              NA    14
 4     4              20    12
 5     5              NA    13
 6     6              NA    14
 7     7              80    13
 8     8              NA    14
 9     9              50    14
10    10              NA    12
# ℹ 3,976 more rows

The result replaces the heading hrs1 with hours_last_week. Values, row order, and dimensions are unchanged. work itself still uses hrs1, because we have not assigned the result back to it.

We can rename several columns in one call and save the returned table:

work_named <- work |>
  rename(hours_last_week = hrs1, schooling_years = educ)

Both new names describe the existing quantities; renaming has not converted their units or changed any answer. The original ID remains alongside each respondent’s measurements.

12.2 Creating and changing columns

mutate() takes a table and returns a table containing new or replaced columns. Bare names refer to existing columns. The expression to the right of = supplies values; the name on the left names the result. First copy the recorded hours into a separate column so that we can inspect the operation without changing the measurement:

work_copy <- work_named |>
  mutate(hours_copy = hours_last_week)
head(work_copy)
# A tibble: 6 × 4
     id hours_last_week schooling_years hours_copy
  <int>           <dbl>           <dbl>      <dbl>
1     1              43              16         43
2     2              NA              16         NA
3     3              NA              14         NA
4     4              20              12         20
5     5              NA              13         NA
6     6              NA              14         NA

ncol(work_copy)
[1] 4

The returned table has the same respondents and one additional column, hours_copy. Each copied value belongs to the respondent on that row. Missing hours remain missing, and the ID, original hours, and schooling values stay alongside the copy. mutate() does not sort or remove respondents. The copy demonstrates column creation; it is not a new measure for analysis.

Using an existing name replaces that column in the returned table rather than adding another column. Repeat the copy using the name that now exists:

work_copy |>
  mutate(hours_copy = hours_last_week)
# A tibble: 3,986 × 4
      id hours_last_week schooling_years hours_copy
   <int>           <dbl>           <dbl>      <dbl>
 1     1              43              16         43
 2     2              NA              16         NA
 3     3              NA              14         NA
 4     4              20              12         20
 5     5              NA              13         NA
 6     6              NA              14         NA
 7     7              80              13         80
 8     8              NA              14         NA
 9     9              50              14         50
10    10              NA              12         NA
# ℹ 3,976 more rows

The result still has four columns, because hours_copy already exists. Its values are unchanged in this particular demonstration because we copied the same source again. In an applied transformation, a different expression would supply replacement values. Check the meaning and unit of a replacement before saving it; Chapter 14 works through that decision with hours and minutes.

Assignment and column naming do different jobs. In work_copy <-, <- saves the entire returned table under an object name. Inside mutate(), hours_copy = names one column in that table. Neither call changes work_named: it still contains only the renamed original columns. Likewise, a pipeline that is printed without assignment returns a result but does not save it over its input.

Keep calculations inside the table whose rows supply their inputs. A column copied or calculated there stays aligned with its respondent. A separately sorted or filtered column may no longer have the same rows in the same order, even if its length looks plausible.

12.3 Text

Quotation marks tell R to treat their contents as text, also called a character value or string. Even digits become text inside quotation marks:

12
[1] 12
"12"
[1] "12"

The first is numeric and the second is character. Printed quotation marks help distinguish them. A string may contain digits, spaces, or punctuation; it need not be a single letter. Use straight quotation marks in code, either single or double.

var_type() takes one object and returns its type without changing it:

var_type(12)
[1] "double"
var_type("12")
[1] "character"

The results are "double" and "character". A double is R’s usual numeric type, including fractional values such as 2.75. Quoted digits remain character values even when they look numeric.

paste() joins its inputs, inserting a space by default:

text <- "hello"
greeting <- paste(text, "R")
greeting
[1] "hello R"
text
[1] "hello"

The result is "hello R". The original text remains "hello"; the joined string is stored separately as greeting.

Joining text can change how missingness appears. Consider an abstract label whose second component is unknown:

missing_component <- NA_character_
missing_label <- paste("Label:", missing_component)
missing_label
[1] "Label: NA"
is.na(missing_component)
[1] TRUE
is.na(missing_label)
[1] FALSE

NA_character_ is a missing character value. The input check returns TRUE, but the joined label is the non-missing string "Label: NA", so its check returns FALSE. paste() has inserted visible text representing the unknown component. Checking only the finished label would miss that unavailable input. If a label requires every component, check their missingness before joining them; a readable string does not establish that all its information was recorded.

12.4 Convert text and numbers

To convert numeric text explicitly, use as.numeric():

number_text <- "12"
number <- as.numeric(number_text)
number
[1] 12
var_type(number_text)
[1] "character"

The returned number is 12. Assignment stores it in number; the original number_text remains character. as.character() makes the reverse conversion:

as.character(number)
[1] "12"

It returns "12" without changing the numeric input. A string with no numeric representation cannot be converted successfully:

converted_text <- as.numeric("hello")
Warning: NAs introduced by coercion
converted_text
[1] NA
is.na(converted_text)
[1] TRUE

R warns that NAs were introduced by coercion, its term for conversion. The output is NA, and is.na() returns TRUE. The failed conversion does not produce zero.

A conversion can succeed while losing part of the text:

code <- "01"
as.numeric(code)
[1] 1
code
[1] "01"

The converted result is 1, losing the leading zero. The original remains "01" because we did not overwrite it. Keep identifiers as text when their formatting matters. Keep a field’s meaning in view: numeric-looking identifiers and category codes are not automatically quantities to average. Chapter 15 develops factor levels and labelled survey scores later.

12.5 Prepare descriptive text

Extra spaces can prevent two otherwise identical labels from matching. str_squish() receives character values and returns character values with surrounding whitespace removed and repeated internal whitespace reduced to one space. It does not change an object unless we assign its result. Use a plain phrase to make the spacing rule visible:

spacing_example <- "  A   short phrase  "
spacing_example
[1] "  A   short phrase  "
str_squish(spacing_example)
[1] "A short phrase"

The quotation marks show where the original spaces occur. The returned phrase keeps the words and their order. This is a syntax demonstration with plain text. Spaces can be meaningful in identifiers, so inspecting the source and understanding its coding rules should precede any automatic cleaning.

Case is another feature of text. str_to_lower() returns a lowercase version without changing the supplied object:

case_example <- "A Short Phrase"
str_to_lower(case_example)
[1] "a short phrase"
case_example
[1] "A Short Phrase"

The result is "a short phrase"; the original retains its capitals. Lowercasing can provide a consistent search form. Neither spacing changes nor a consistent case establishes that two records identify the same person.

12.5.1 Labels from recorded answers

Can we describe respondents by their recorded sex and highest degree without changing those source answers? Select the three columns together so their rows remain aligned:

respondent_labels <- gss24 |>
  select(id, sex, degree)
head(respondent_labels)
# A tibble: 6 × 3

  <int> <fct>  <fct>

id identifies the respondent. sex and degree are the prepared category columns already encountered in the GSS tables. Use as.character() to obtain their displayed category text. Convert one column first and keep its source:

  mutate(sex_text = as.character(sex))

respondent_labels <- respondent_labels |>
  mutate(description_search = str_squish(description))

respondent_labels <- respondent_labels |>
  mutate(description_search = str_to_lower(description_search))

12.6 Review

  • rename() changes column names without changing their values or row order.
  • mutate() adds a column when its output name is new and replaces a column when that name already exists.
  • A column expression uses values from the same row; preserve the connection to the observation’s ID.
  • Assignment saves the returned table. Printing a result leaves the input object unchanged.
  • as.numeric() and as.character() return explicit conversions; check failed conversions and formatting losses.
  • paste() joins aligned text inputs; a visible label can conceal a missing component and need not identify a respondent.
  • str_squish() and str_to_lower() prepare derived text while source values remain available.
