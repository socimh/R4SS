15  Strings and factors

Survey answers such as marital status and confidence in institutions describe categories. A table needs readable category names and a useful display order. A questionnaire score needs a separate decision about which numbers represent which answers. This chapter distinguishes those tasks so that changing a label does not silently change an analysis.

By the end of this chapter, you will be able to:

  • Create a factor and inspect its category levels.
  • Search and transform text while retaining recorded names and codes.
  • Change category order without rearranging respondents.
  • Relabel or combine categories while preserving missing answers.
  • Encode answers as labelled numeric scores, count available answers, and state a rule for combining items.

We use the prepared 2024 GSS extract, the column-creation method from Chapter 12, and the numeric recoding from Chapter 14. Frequency tables from Chapter 8 help us check each change. The GSS examples describe the sample without survey weights. A separate, contiguous text application reuses the captured aggregate country data because its names are character fields.

Prepare the extract following Appendix A, then restore the saved file in your project folder:

library(tidyverse)
library(tidystata)
gss24 <- readRDS("gss24.rds")

15.1 Create factors

A factor represents categories with a defined set of possible values, called levels. A character column stores text; a factor also records which categories are allowed and their order. The prepared GSS already uses factors for categorical answers.

First, recreate the numeric age groups from Section 14.4. This chapter starts from the saved extract rather than depending on objects left in your session:

people <- gss24 |>
  select(id, age)
age_groups <- people |>
  mutate(age_group = stata_recode(
    age,
    18:34 ~ 1,
    35:64 ~ 2,
    65:max ~ 3,
    .default = NA
  ))

The codes 1, 2, and 3 identify age bands, not ages in years. Now give these codes readable category labels by making a factor. The levels argument lists the codes in display order; labels supplies their corresponding text. Here c() combines each set of three values:

gss_ages <- age_groups |>
  mutate(age_group = factor(
    age_group, levels = c(1, 2, 3), labels = c("18-34", "35-64", "65+")
  ))
head(gss_ages)
# A tibble: 6 × 3
     id   age age_group
  <int> <dbl> <fct>    
1     1    33 18-34    
2     2    64 35-64    
3     3    69 65+      
4     4    19 18-34    
5     5    70 65+      
6     6    53 35-64    

nrow(gss_ages)
[1] 3986

factor() returns the categorical values. All 3986 respondents remain in their original order. Changing a level order does not move rows or change anyone’s age. A missing age remains missing rather than becoming a fourth category.

levels() receives a factor and returns its category names in level order. Extract the new factor with the familiar $:

levels(gss_ages$age_group)
[1] "18-34" "35-64" "65+"

The three labels appear in the order we supplied. This list describes the factor’s categories, rather than the order in which respondents appear.

An explicitly supplied level list must cover the known input codes: a non-missing value absent from that list becomes missing. Check the codes and the correspondence between levels and labels. The order controls display and sorting; it does not establish equal distances between categories or turn category codes into years of schooling.

To see the categories alongside their frequencies, use the familiar tab():

gss_ages |>
  tab(age_group)

15.2 Change category order

Suppose a presentation needs the oldest age band first. fct_relevel() from forcats, loaded by tidyverse, moves the named levels to the beginning in the order supplied. Levels not named follow in their existing order. Save its result in a new column so that the original ordering remains available:

age_display <- gss_ages |>
  mutate(age_group_oldest_first = fct_relevel(age_group, "65+", "35-64"))
levels(age_display$age_group_oldest_first)
[1] "65+"   "35-64" "18-34"
age_display |>
  tab(age_group_oldest_first)
# A tibble: 4 × 6
  age_group_oldest_first     n percent   cum valid valid_cum
  <fct>                  <int>   <dbl> <dbl> <dbl>     <dbl>
1 65+                      912   22.9   22.9  23.6      23.6
2 35-64                   1964   49.3   72.2  50.9      74.5
3 18-34                    983   24.7   96.8  25.5     100  
4 NA                       127    3.19 100    NA        NA

The new order is 65+, 35-64, then 18-34. Each band still contains the same respondents, and the rows of age_display remain in their original order. arrange() sorts whole observations; fct_relevel() changes category order within a column. A factor with deliberately arranged levels is still an ordinary factor. R also has an ordered-factor class, which has additional consequences for comparisons and modeling; changing the display order here does not create that class.

15.3 Relabel and combine categories

A publication may need a fuller label than “65+”. fct_recode() changes level names. Write the new name on the left of = and the existing name on the right. Levels not named remain unchanged:

age_labels <- gss_ages |>
  mutate(age_group_label = fct_recode(age_group, "65 and older" = "65+"))
age_labels |>
  tab(age_group_label)
# A tibble: 4 × 6
  age_group_label     n percent   cum valid valid_cum
  <fct>           <int>   <dbl> <dbl> <dbl>     <dbl>
1 18-34             983   24.7   24.7  25.5      25.5
2 35-64            1964   49.3   73.9  50.9      76.4
3 65 and older      912   22.9   96.8  23.6     100  
4 NA                127    3.19 100    NA        NA

Only the label changes. The age-band membership and frequencies agree with the original factor, including its missing answers. A clearer label does not create a more precise measurement.

Combining categories changes their membership. fct_collapse() takes a new category name on the left and the old levels to combine on the right. Here c() supplies the two younger age bands:

age_bands <- gss_ages |>
  mutate(age_band = fct_collapse(age_group, "Under 65" = c("18-34", "35-64")))
age_bands |>
  tab(age_band)
# A tibble: 3 × 6
  age_band     n percent   cum valid valid_cum
  <fct>    <int>   <dbl> <dbl> <dbl>     <dbl>
1 Under 65  2947   73.9   73.9  76.4      76.4
2 65+        912   22.9   96.8  23.6     100  
3 NA         127    3.19 100    NA        NA

“Under 65” now includes everyone previously in either younger band; the unnamed “65+” level remains. Unknown ages remain missing. We retain the original age_group column because the broader grouping discards the distinction between the two younger bands. Choose categories for the research question, and avoid combining substantively different answers merely to shorten a table.

15.4 Combine questionnaire items

The GSS asks about confidence in major companies, education, and medicine. We use these three items to demonstrate a score, without claiming they form a validated scale. A common spelling in variable names does not establish that questions belong together. Select these items because their meanings suit the teaching question:

confidence <- gss24 |>
  select(id, conbus, coneduc, conmedic)

The answers are factors. Define numeric scores explicitly: hardly any confidence is 1, only some is 2, and a great deal is 3. Higher values then mean greater confidence. Store the category names in the intended order, and apply that order to one item before converting any scores:

score_levels <- c("hardly any", "only some", "a great deal")
business_ordered <- factor(confidence$conbus, levels = score_levels)
levels(business_ordered)
[1] "hardly any"   "only some"    "a great deal"

The result lists hardly any, only some, then a great deal. The original conbus factor puts a great deal first, so its original order does not match the score direction we chose. The level list must cover all recorded answers: a value absent from it would become missing in factor().

Tidystata’s encode() receives a factor and returns labelled integer codes. The first supplied level receives 1, the second 2, and the third 3; the level text remains attached as value labels. It uses the factor order rather than choosing a score direction. Encode just the ordered business item:

business_score <- encode(business_ordered)
head(business_score)
<labelled<integer>[6]>
[1]  3  2  2 NA  2  1

Labels:
 value        label
     1   hardly any
     2    only some
     3 a great deal

Recorded answers now have numeric scores with their meanings attached. Unknown answers remain missing. Neither assignment changes the original factor in confidence or gss24.

Apply these checked ordering and encoding steps separately to all three items:

confidence_scores <- confidence |>
  mutate(
    conbus = encode(factor(conbus, levels = score_levels)),
    coneduc = encode(factor(coneduc, levels = score_levels)),
    conmedic = encode(factor(conmedic, levels = score_levels))
  )
head(confidence_scores)
# A tibble: 6 × 4

  <int> <int+lbl>         <int+lbl>         <int+lbl>        
1     1  3 [a great deal]  3 [a great deal]  3 [a great deal]
2     2  2 [only some]     2 [only some]     3 [a great deal]

The returned table keeps the same respondents and replaces the three factors with their scores. The source factors remain in confidence. Some questions were not asked on every ballot, so an unavailable answer need not indicate refusal.

15.4.1 Apply the same scoring rule to the battery

The three calls above use the same level order and conversion. After checking them separately, we can use across() from Chapter 13 to express the shared rule once:

confidence_scores_block <- confidence |>
  mutate(across(
    conbus:conmedic,
    \(x) encode(factor(x, levels = score_levels))
  ))
identical(confidence_scores_block, confidence_scores)
[1] TRUE

As in Section 13.2.1, \(x) supplies an unnamed function. For each selected column, across() supplies that column as x; the function orders its categories and encodes the result. It returns one score per original response. The comparison returns TRUE, including values, missingness, and value labels. The scores replace columns in the returned scoring table, while confidence retains the original answers. The common rule is justified by the three items’ shared response scale, not merely by their names. Do not reuse it for a battery containing differently worded or reverse-scored items without inspecting those definitions.

15.4.2 Require complete responses

Use row_non_miss() from Chapter 13 to count recorded answers before calculating a score. As before, count just the three items and exclude id:

confidence_coverage <- confidence_scores |>
  mutate(n_answered = row_non_miss(conbus, coneduc, conmedic))
tab(confidence_coverage, n_answered)
# A tibble: 4 × 6
  n_answered     n percent   cum  valid valid_cum
       <int> <int>   <dbl> <dbl>  <dbl>     <dbl>
1          0  1351  33.9    33.9 33.9        33.9
2          1    10   0.251  34.1  0.251      34.1
3          2    73   1.83   36.0  1.83       36.0
4          3  2552  64.0   100   64.0       100

Every respondent has a count from 0 through 3; 3 identifies complete responses. Zero available answers is not a confidence score of zero and does not establish why answers are unavailable. The scores and source respondents remain unchanged by this count.

For this demonstration, require all three answers. Tidystata’s row_mean() calculates one arithmetic mean per respondent across the supplied columns. It omits missing answers by default; na.rm = FALSE instead makes the score missing whenever any of the three answers is missing:

scored_confidence <- confidence_coverage |>
  mutate(mean_score = row_mean(conbus, coneduc, conmedic, na.rm = FALSE))
scored_confidence |>
  select(id, n_answered, mean_score) |>
  head()
# A tibble: 6 × 3
     id n_answered mean_score
  <int>      <int>      <dbl>
1     1          3       3   
2     2          3       2.33
3     3          3       2.67
4     4          0      NA   
5     5          3       1.67
6     6          3       1.67

The function combines values belonging to the same respondent, giving each item equal weight. With na.rm = FALSE, a missing item makes the score missing; we do not average two answers as though they were three. Complete scores run from 1 to 3. This complete-response rule is a teaching choice, not a recommendation for a validated confidence scale. The calculation neither fills source answers nor establishes equal spacing or measurement validity.

15.6 Count characters

nchar() receives text and returns the number of characters inside its quotation marks:

text <- "hello"
nchar(text)
[1] 5
nchar("01")
[1] 2

The results are 5 and 2. Both the zero and the one in "01" count; quotation marks do not. Counting characters neither converts the text to numbers nor changes the original string.

As with arithmetic in Section 14.3, text operations act element by element. c() combines strings in their written order:

words <- c("one", "two", "three")
var_type(words)
[1] "character"
nchar(words)
[1] 3 3 5
paste("Word:", words)
[1] "Word: one"   "Word: two"   "Word: three"

The type is "character", and the character counts are 3, 3, and 5. The familiar paste() returns "Word: one", "Word: two", and "Word: three". Its single prefix applies to every input value, following the single-value repetition rule from Section 14.3. Text operations on a named column likewise return one result per row.

15.7 Prepare names for searching

Chapter 12 introduced numeric text, explicit conversion, paste(), spacing, and lowercase search forms. Those tools return transformed values without replacing the source unless assigned over it. Here we apply them to recorded country names. A description remains different from an identifier, and joined text can still conceal missing source components.

First select one year so that a name search does not repeat each entity across many years. Use the familiar str_squish() to supply a spacing rule in a separate column:

names_2023 <- owid |>
  filter(Year == 2023) |>
  select(Entity, Code, Year) |>
  mutate(entity_clean = str_squish(Entity))

This applies the rule without asserting that every recorded name needs correction. Now create a lowercase search form from that result:

names_2023 <- names_2023 |>
  mutate(entity_lower = str_to_lower(entity_clean))
names_2023

The new column provides a consistent search form; Entity remains suitable for display. Code remains text because its role is identification rather than arithmetic. Changing a code’s storage to a number can discard meaningful leading zeros in other datasets. Neither a digit-like appearance nor a short code makes a field a quantitative measurement.

Lowercasing is a specific transformation, not a way to reconcile different naming conventions. It cannot establish that two differently named records refer to the same entity. If names are used to combine datasets, inspect unmatched records and use an appropriate checked identifier, following Chapter 20.

15.8 Search names

Which names contain the word fragment United? Begin by defining what we want to match. fixed() constructs a literal search pattern, whose characters will be matched as written rather than interpreted as special pattern symbols:

united_pattern <- fixed("United")

This saves a case-sensitive pattern; it has not yet searched any names. str_detect() receives strings and a pattern, then returns one logical result per string. Inspect that result before using it to select rows:

head(str_detect(names_2023$Entity, united_pattern))
[1] FALSE FALSE FALSE FALSE FALSE FALSE

Each displayed TRUE or FALSE refers to the corresponding entity name. Detection returns a result without changing those names. Inside the familiar filter(), its TRUE values retain matching rows:

united_names <- names_2023 |>
  filter(str_detect(Entity, united_pattern))
united_names
# A tibble: 4 × 5
  Entity                       Code   Year entity_clean             entity_lower
  <chr>                        <chr> <dbl> <chr>                    <chr>       
1 United Arab Emirates         ARE    2023 United Arab Emirates     united arab…
2 United Kingdom               GBR    2023 United Kingdom           united king…
3 United States                USA    2023 United States            united stat…
4 United States Virgin Islands VIR    2023 United States Virgin Is… united stat…

The result contains 4 entity names in the selected year. Read the entire names: a shared fragment does not imply that the entities describe the same population. The original Entity, Code, and Year remain available to identify each match.

We can search the normalized column instead. The lowercase pattern must match its case:

names_2023 |>
  filter(str_detect(entity_lower, fixed("united")))
# A tibble: 4 × 5
  Entity                       Code   Year entity_clean             entity_lower
  <chr>                        <chr> <dbl> <chr>                    <chr>       
1 United Arab Emirates         ARE    2023 United Arab Emirates     united arab…
2 United Kingdom               GBR    2023 United Kingdom           united king…
3 United States                USA    2023 United States            united stat…
4 United States Virgin Islands VIR    2023 United States Virgin Is… united stat…

This returns the same entities. We chose a consistent form for searching without changing the displayed names. A missing string would give an unknown detection result, NA; it would not prove that the pattern was absent. As in earlier filtering lessons, filter() retains only TRUE. Check unknown source names separately if they occur in the data you analyze, rather than replacing unknown matches with FALSE.

15.8.1 Match a position

A regular expression is a pattern whose symbols can describe positions or groups of characters. We need only a few symbols here. ^ means the start of a string, and $ means its end. Without fixed(), stringr interprets these as pattern instructions. Compare a name starting with United with a name ending in States:

starts_united <- names_2023 |>
  filter(str_detect(Entity, "^United"))
ends_states <- names_2023 |>
  filter(str_detect(Entity, "States$"))
starts_united
# A tibble: 4 × 5
  Entity                       Code   Year entity_clean             entity_lower
  <chr>                        <chr> <dbl> <chr>                    <chr>       
1 United Arab Emirates         ARE    2023 United Arab Emirates     united arab…
2 United Kingdom               GBR    2023 United Kingdom           united king…
3 United States                USA    2023 United States            united stat…
4 United States Virgin Islands VIR    2023 United States Virgin Is… united stat…

ends_states
# A tibble: 1 × 5
  Entity        Code   Year entity_clean  entity_lower 
  <chr>         <chr> <dbl> <chr>         <chr>        
1 United States USA    2023 United States united states

The first result has 4 rows; the second has 1. In particular, a name containing United States can continue with other words and therefore fail the end-of-string test. These differences are consequences of the search rule, not discrepancies in the records.

Choose literal matching when you want particular characters anywhere in a name. Add a position rule only when position is part of the question. Placing ^ inside fixed() would instead search for an actual caret character. Text tools follow the instructions we supply; they cannot infer the population we meant to select.

15.9 Replace and remove text

Text changes can make a search form or display label useful. str_replace_all() receives text, a search pattern, and replacement text. It returns a string with every match replaced; supplying fixed() makes the match literal. Shorten “and” to an ampersand only in a separate display column:

name_versions <- names_2023 |>
  mutate(entity_display = str_replace_all(Entity, fixed(" and "), " & "))
name_versions |>

The display column changes names containing the exact spaced word. The original Entity remains. str_remove() instead removes the first match and needs no replacement argument. Remove the literal qualifier ” (country)” only in a separate search column:

name_versions <- name_versions |>
  mutate(entity_search = str_remove(Entity, fixed(" (country)")))

The output displays the affected names beside their originals. “Trinidad and Tobago” becomes “Trinidad & Tobago” only in the display form. “Micronesia (country)” loses its qualifier only in the search form. These changes do not establish that shortened names are unique or identify the same geography as another record. Preserve Entity and Code; a convenience label is not automatically a joining key.

We can apply one shared text operation to several columns with the across() method from Section 13.2. Lowercase versions of both names and codes allow lowercase search queries. Choose these two character columns explicitly and retain their original spelling:

name_searches <- names_2023 |>
  mutate(across(c(Entity, Code), str_to_lower, .names = "{.col}_search"))
name_searches |>
  filter(str_detect(Entity_search, fixed("united")) | Code_search == "usa")

Lowercasing already consistent text may leave it unchanged; do not describe that as repairing an observed error. Apply an operation across columns only when their meanings support the same rule. We do not apply text cleaning to the numeric year or the life-expectancy measurement.

15.10 Review

  • factor() defines categories and their level order; levels() lists those levels.
  • fct_relevel() changes category order without rearranging respondents.
  • fct_recode() changes labels; fct_collapse() combines categories.
  • encode() converts explicitly ordered factor levels to labelled numeric codes; choose score direction before encoding.
  • row_mean() combines numeric items using an explicit missing-answer rule; count available items before interpreting the score.
  • across() expresses a shared conversion after individual checks; response definitions still determine whether the rule is appropriate.
  • str_detect(), fixed(), and anchors control searches; str_replace_all() and str_remove() produce derived text forms.
  • Preserve original categories and unknown answers; joined text can conceal missing inputs. Category codes do not establish equal spacing, and a calculated score is not automatically a validated scale.

The next chapter, Chapter 16, applies the same practice of retaining source values to dates and calendar components. Chapter 17 later splits these recorded entity names into word lists. Later, Chapter 19 uses categories to calculate within groups and reshape questionnaire items. The optional programming part explains values, vectors, and other R data structures in more detail; return to it when you need to examine the mechanics behind these table operations.
